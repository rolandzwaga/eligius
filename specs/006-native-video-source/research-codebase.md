# Research (codebase): replace the video.js player with a native HTMLVideoElement

Date: 2026-11-01. Branch: `feat/native-video-source`. Read-only research; nothing but this file was written.
Line numbers refer to the working tree at the start of the research (`git status` clean, HEAD `30f2ac79`). Where a line number is prefixed with `~` it is approximate.

## 0. Findings that change the plan

1. `src/tools/type-tools/check-dist-types.ts`, `typedoc.json`, `typedoc-metadata.json`, `src/test/setup.ts`, `src/engine-factory.ts` (code) and `src/configuration/timeline-provider-overrides.ts` contain NO video.js reference. The task text and CLAUDE.md suggest check-dist-types does; it does not (see section 5), so nothing needs to change there. The full list of places that do mention video.js is in section 8.
2. The JSON schema does not mention `options` today. `IPositionSourceConfig` (`src/configuration/types.ts:174-216`) ends in an index signature `[key: string]: unknown` (`:215`), which the generator renders as `additionalProperties: {description: ...}` (`jsonschema/eligius-configuration.json:191-193`). `options` (and any other unknown key) is currently ACCEPTED by the schema. "The schema no longer allows it" therefore needs an explicit mechanism (section 4), not just a deletion.
3. The resolver only validates provider-specific settings for timelines that carry a `positionSource` override (`configuration-resolver.ts:250`, `if (isDefined(timeline.positionSource))`). The type-level settings `timelineProviderSettings.<type>.positionSource` are never inspected for provider-specific keys. Rejecting `options` must therefore cover BOTH locations (section 3).
4. `hasRequiredSetting` (`configuration-resolver.ts:385-397`) and `_getSources` (`video-position-source.ts:443-446`) both special-case `options.sources`; both lose that fallback.
5. Native `<source>` children do not report load failure on the `<video>` element: `error` fires on the `<source>` element (non-bubbling), `video.error` stays `null` and `networkState` becomes `NETWORK_NO_SOURCE (3)`. A plain `video.addEventListener('error', ...)` would leave `init()` pending forever (the hang bug the contract in section 1 item 4 forbids). Use a capture-phase listener (`addEventListener('error', h, true)`) or listen on the `<source>` elements; only the error of the LAST `<source>` means "all failed" (section 9).
6. `loop`: the engine sets `source.loop` AFTER `init()` (`eligius-engine.ts:809` and `:944`, the latter after `_prepareProvider` at `:939`), and `_handleEnded` implements looping itself. The native element must NOT get `loop = true` (it would suppress `ended`). The old code passes `loop: this.loop` to video.js at creation (`video-position-source.ts:389`), which is always `false` at that moment.
7. jsdom 30.1.3 does not implement `HTMLMediaElement.load/play/pause` (they call `notImplementedMethod`, `node_modules/jsdom/lib/jsdom/living/nodes/HTMLMediaElement-impl.js:99-112`), `duration` is a read-only `NaN` (impl `:31`), `currentTime` is a writable plain value (impl `:27`), and nothing fires `canplay`/`seeked`/`playing`/`ended`. The new spec must stub the prototype methods and dispatch events by hand (section 2).
8. `package-lock.json` holds video.js plus about a dozen video.js-only transitive packages, all `"dev": true` (section 5). Let `npm uninstall video.js` prune them; do not hand-edit.

## 1. Behavioural contract of VideoPositionSource that must be preserved

File: `F:\projects\eligius\eligius\src\timelineproviders\position-sources\video-position-source.ts` (543 lines). Base class: `src/timelineproviders/position-sources/base-position-source.ts`.
1. **Constructor is side-effect free** (`:145-150`): `super(0)` (duration starts at 0), stores the config, generates an element id `video-<uuid>` (`:149`, `crypto.randomUUID?.() ?? Math.random()...`). It touches no DOM and loads nothing. `engine-factory-create-timeline-providers.spec.ts` constructs real instances through a mock importer, so the constructor must stay DOM-free. The engine factory passes `{...options, duration: timeline.duration}` (`engine-factory.ts:529-534`); `duration` is ignored by this class and must stay ignored.
2. **init rejects when the container is missing** (`:158-165`): `new Error("VideoPositionSource: container not found for selector '<selector>'")`, tested with `$(selector).length === 0`. No element is created. Test: spec `:751`.
3. **init rejects when sources are missing or empty** (`:167-177`): `new Error("VideoPositionSource: 'sources' is required (an array of {src, type})")` when not an array or length 0. It runs BEFORE the element is created (spec `:1013-1023` asserts `#video-container video` is null). Today sources come from `options.sources ?? sources` (`:443-446`); the new code reads only `config.sources`. Tests: spec `:1013`, `:1026`.
4. **init resolves on the first `canplay`, rejects on `error`** (`:430-432` and `:418-428`). Error text: `VideoPositionSource: failed to load video (<comma-joined src list>)`, plus `: <mediaError.message>` when present. Both are one-shot; `_settleInit` (`:452-463`) is idempotent, so the first event wins. Test: spec `:737`. See section 0 item 5 for the `<source>` error caveat.
5. **The element is in the DOM before loading starts** (`:182-183`, `:468-472`): a `<video id=... class="video-js">` is appended to `$(selector)`. New code: append a `<video>` with `<source src type>` children, `controls=false`, `preload='auto'`, `poster` only when defined (`:393-395`; tests `:1048`, `:1060`), no native `loop`, no `autoplay`.
6. **destroy before init settles** (`:208-213`, `:186-204`): `doDestroy` calls `_settleInit(new Error('VideoPositionSource: destroyed before init completed'))`, which rejects the pending init; the async continuation of the video.js load checks `this._pendingInit !== pendingInit` and bails (`:189-192`, `:200`). With a native element there is no async load step, so the guard reduces to: destroy removes all listeners and rejects init. Test: spec `:779` (asserts rejection matching `/destroyed/`). Its second half ("videojs is not called") has no native equivalent; replace it with "no listener fires after destroy".
7. **seek always settles** (`:265-307`):
   - destroyed or not initialised: resolves `this.getPosition()` and does not touch the player (`:266-268`; spec `:1164`: result 0, element untouched).
   - resolves on `seeked` with the element's `currentTime`, calling `setPosition(actual)` first (`:285-292`; specs `:507`, `:538`).
   - settles with the current time on `error` and on `emptied` (`:295-297`; specs `:1071`, `:1089`), falling back to `getPosition()` if the player is gone.
   - settles when the source is destroyed first: `doDestroy` calls every pending settle with the current time (`:215-218`, `:300`; spec `:932`).
   - removes all three listeners once settled (`:279-281`; spec `:1102`).
   - registers its listeners BEFORE assigning `currentTime` (`:301-305`).
   - pending seeks live in `_pendingSeeks` (`:134`).
8. **Container ready on the first `playing`** (`:412-416`, `:535-542`): one-shot, every registered callback called once; callbacks registered afterwards run immediately (`:330-336`; specs `:246`, `:658`, `:677`, `:916`). `getContainer()` returns `$(config.selector)` (`:318-320`), NOT the video element; the engine uses it as the content container (`eligius-engine.ts:410`). Keep that. Latent leak (not contract): `_containerReadyCallbacks` is not cleared in `doDestroy` and `_containerReady` is never reset.
9. **Duration from the media** (`:347-349`): `player.duration() ?? 0`. video.js returned 0 before metadata; native `video.duration` is `NaN` before metadata and `Infinity` for unbounded streams. The new `getDuration()` must return 0 for non-finite values, otherwise the engine (`eligius-engine.ts:392, 605, 647, 814, 1135`) compares against `NaN`. Test: spec `:232` (120).
10. **Loop handling in `ended`** (`:509-530`): ignored unless `state === 'active'`; emits boundary `end`; if `this.loop`: `currentTime = 0`, `setPosition(0)`, emit `start`, replay with `play()?.catch(() => {})` (handled rejection; optional chaining tolerates stubs returning `undefined`); otherwise `this.deactivate()`. `this.loop` is read at event time, so the native `loop` attribute must never be set. Tests: spec `:565`, `:584`, `:602`, `:897`.
11. **deactivate resets currentTime** (`:356-370`): no-op when inactive; stops ticking when active; `currentTime = 0`; then `super.deactivate()` (state inactive, position 0, activation token bump). Test: spec `:359`.
12. **startTicking awaits play() and propagates rejection** (`:236-241`): `await this._player?.play()`. `BasePositionSource.activate` reverts the state and rethrows; a superseded activation resolves silently (base class `activate()`). `stopTicking` pauses (`:243-246`). The base `destroy()` calls `stopTicking()` before `doDestroy()` when active. Tests: spec `:867`, `:884`, `:1118`. Native `play()` returns a Promise in browsers and `undefined` in unstubbed jsdom; keep `await` so both work.
13. **No handler leaks after destroy** (`:220-224`, `:480-490`): every listener is tracked in `_eventHandlers` and removed in `doDestroy`; seek listeners are removed on settle. New code: `addEventListener`/`removeEventListener` with stored references, including the one-shot `canplay`, `error` and `playing` handlers, which video.js removed itself when they fired but which must ALSO be removed on destroy when they never fired. Test: spec `:703`.
14. **Element removal on destroy** (`:226-233`): dispose the player and remove the element via `$('#id').remove()`. New code removes by element reference and also releases the media: `pause()`, remove `<source>` children and the `src` attribute, call `load()` (guard: jsdom logs "not implemented"), then `remove()`.
15. **Position reported only while active** (`:495-504`): the `timeupdate` handler returns unless `state === 'active'`; else `setPosition(currentTime)`. `setPosition` stores the value but only calls position callbacks when active (base class). A suspended `timeupdate` is ignored entirely (spec `:471`). `suspend()` preserves the position (spec `:325`). Native `timeupdate` cadence (about 250 ms) is the same as under video.js, which relays the native event.
16. **State machine is inherited**: `activate()` on an active source is a no-op, `suspend()` only from active, resume from suspended calls `play()` again (spec `:380`). Do not override.
17. **Pre-init calls are harmless**: `seek`, `startTicking`, `stopTicking`, `getDuration`, `deactivate` all use `this._player?.` and no-op before init (activate before init resolves without playing). Keep.

Public surface to keep: `export interface VideoSource {src; type}`, `export interface VideoPositionSourceConfig {selector; sources; poster?}` (minus `options`), `export class VideoPositionSource extends BasePositionSource implements ISeekable, IContainerProvider` with `seek`, `getContainer`, `onContainerReady`, `getDuration`, `deactivate` and the protected `doInit/doDestroy/startTicking/stopTicking`. The class JSDoc (`:82-115`), `selector` doc (`:60`), `sources` doc (`:64-68`, mentions `options.sources`), `options` doc (`:75-79`) and `getDuration` doc (`:342-346`) mention video.js and must be rewritten.

### Where to reject `options`

A new pass in `ConfigurationResolver.process`, before the deep copies are relied on (so the raw configuration is judged), covering both locations:
- `timelineProviderSettings.<type>.positionSource.options` for every own key of `timelineProviderSettings` (guard `isObject`). Today only the types used by timelines are looked at (`:~236-243`), so a loop over the keys is new. A type no timeline uses is rejected too (fail fast).
- `timelines[i].positionSource.options` (the override), in or next to `assertProviderOverride`. For an override without `systemName`, the effective system name is inherited from the type settings (use `effectivePositionSource`).
- Scope decision for the plan: `IPositionSourceConfig` documents its index signature as "Additional configuration options passed to the position source constructor. Use this for custom position source implementations" (`types.ts:211-214`), so a custom source may legitimately take an `options` key. The maintainer decision reads as VideoPositionSource only. Recommended: reject only when the effective `systemName` is `'VideoPositionSource'`. Flag for critics.
- Proposed message (names the path, suggests the fix): `Invalid configuration at timelineProviderSettings.mediaplayer.positionSource.options: 'options' is no longer supported by VideoPositionSource (removed in 4.0.0 together with video.js). Put 'sources' and 'poster' directly in timelineProviderSettings.mediaplayer.positionSource and delete 'options'. See CHANGELOG.md.`
- Existing resolver test to flip: `configuration-resolver.spec.ts:1461-1472` ('given a VideoPositionSource override with sources in options, when process is called, then it is accepted') must become a rejection test naming `timelines[0].positionSource.options`. New tests: type-level rejection; override rejection; inherited system name (override without `systemName` over a video type); a custom source with `options` still accepted (if the scope decision holds); message names the JSON path.
- Programmatic use (`new VideoPositionSource({... options})`, or `EngineFactory.createPositionSourceForTimeline` called directly) bypasses the resolver. TypeScript callers get a compile error once `options` leaves `VideoPositionSourceConfig`; JS callers do not. Decide whether `doInit` should also reject a stray `options` key (recommended, cheap).

### Fluent API

`src/configuration/api/timeline-provider-settings-editor.ts`: `DEFAULT_POSITION_SOURCES.video = 'VideoPositionSource'` (`:17`); `setPositionSourceType('video', options?)` (`:119`, deprecated) already types `options` as `{selector?, tickInterval?, poster?, sources?}` and has no `options` key; `setPositionSourceByName(systemName, options?: Record<string, unknown>)` (`:102`) spreads into the config and would let a caller pass `{options: {...}}`, which the resolver then rejects. No video.js mention, no required change. The Eligian DSL emits plain JSON `systemName/selector/sources/poster`, so it keeps working.

## 9. Design notes for the native implementation (hazards for the critic)

- **Error plumbing** (section 0 item 5): a `<source>` failure dispatches `error` at the `<source>` and does not bubble; use a capture listener on the video element. Only the last `<source>` failing means "all sources failed" (the browser tries the next candidate after an earlier one fails), so an error from an earlier `<source>` must not reject init; check `source === lastSource` or `video.networkState === HTMLMediaElement.NETWORK_NO_SOURCE`. `video.error?.message` is often empty; fall back to `code`. The same applies to the seek abort via `error`.
- **Listener order**: attach `canplay`/`error`/`playing`/`timeupdate`/`ended` BEFORE appending the element (or its sources) to the DOM, so a cached source cannot fire before the listener exists. The old code attached them in the player-ready callback.
- **`play()`**: Promise in browsers, `undefined` in unstubbed jsdom. `startTicking` must `await` it; `_handleEnded` must use `?.catch`. The play/pause/play AbortError test (`:1118`) mirrors a real Safari/Chrome behaviour and stays.
- **Attributes**: the video.js version set `controls:false`, `controlBar:false`, `liveui:false`, `autoplay:false`, `preload:'auto'`, `loop: this.loop`. Native: `controls=false`, `autoplay=false`, `preload='auto'`, never `loop`. `playsInline = true` (iOS) and `muted` are product decisions for the planner.
- **Seeking**: assigning `currentTime` before metadata is deferred and fires no `seeked` until loaded; fine after `canplay`. The old code did not clamp; keep unless the planner wants it.
- **`duration`**: non-finite -> 0 (guarantee 9). `canplay` implies `loadedmetadata`, so the engine's post-init read is valid.
- **DOM/CSS migration**: video.js wrapped the `<video class="video-js">` in a generated `div.video-js` with control bar, poster and spinner nodes, and sized itself. CSS targeting `.video-js`/`.vjs-*` stops applying; the migration steps must say so. The native element needs a documented class (suggest `eligius-video`) and a sizing decision (for example `width: 100%`).
- **Poster**: `video.poster = url` only when defined; the browser shows it until the first frame.
- **Layout interplay**: the engine does `container.html(layoutTemplate)` on the engine root at init (`eligius-engine.ts:914`) and `$(containerSelector).empty()` in destroy (`:1240`). The video source's `selector` may sit inside the layout template; source init happens after layout creation today (`_prepareProvider` at `:939`) and that does not change.
- **Duplicate init**: a second `init()` currently appends a second element and leaks the first; not contract, optional guard.
- **Validation location**: `selector`/`sources` checks stay in `doInit` (tests expect `init()` to reject, not the constructor to throw).
- **Source `type`**: set as the `type` attribute of `<source>` so the browser skips unsupported containers without a request.
- **Tick resolution**: `timeupdate` about 4 Hz, unchanged from video.js; `requestVideoFrameCallback` is out of scope.
- **Memory**: on destroy remove `src`, remove `<source>` nodes and call `load()` so the browser drops the connection; a removed element can otherwise keep downloading.
- **API stability**: removing `options` from `VideoPositionSourceConfig` and the peer dependency is the breaking change that justifies 4.0.0 (CLAUDE.md "Public API stability").
