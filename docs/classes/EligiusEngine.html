    Class EligiusEngine

    The Eligius timeline engine with explicit, testable API.

    This engine is responsible for starting and stopping the given timeline provider and triggering the actions associated with positions along the timeline.

    The engine reports its state through its own event emitter (see EngineEvents). Mapping those events to eventbus broadcasts, and eventbus commands such as timeline-play-request to engine calls, is done by EngineEventbusAdapter, which EngineFactory.createEngine connects. An engine constructed directly needs that adapter connected to be driven through the eventbus.

    Transport commands are serialised: init(), start(), seek(), switchTimeline() and the action cleanup of stop() run one after the other, in call order; a command called while another one runs waits for it. A later seek(), stop() or destroy() supersedes a seek() that has not finished. A later pause(), stop() or destroy() cancels a start() that has not activated the timeline yet, and keeps a pending switchTimeline() from starting playback. pause() and the synchronous part of stop() take effect at once. After destroy(), pending commands do nothing more and new ones are ignored; a pending init() rejects.

    destroy

    • destroy(): Promise<void>

      Cleans up all the necessary parts that the engine initialized.

      • It stops the active position source and cancels pending commands.
      • It ends the currently active timeline actions and the init actions that started.
      • It detaches the controllers still attached to elements inside the engine root (those that no end operation removed).
      • It removes all its eventbus listeners.
      • It destroys all of its position sources and container providers.
      • It empties the HTML element indicated by the containerSelector configuration property.

      Every step runs even when an earlier one fails. Errors are rethrown at the end (an AggregateError when there is more than one). Calling it again returns the same promise; the teardown runs once.

      Returns Promise<void>

    seek

    • seek(position: number): Promise<number>

      Seek to a specific position.

      Ends the active actions that do not cover the position and, once those ends have finished, starts the ones that do. The returned promise resolves when the starts have begun; it does not wait for start operations to finish. Failing actions are reported through the error event. Other commands only wait for the source to seek, not for the end operations. A later seek() or stop() supersedes this one: it then resolves with the position at that moment without emitting seekComplete, and its starts that had not run yet are dropped. When a switchTimeline() replaces the timeline before the seek's starts have begun, it resolves with the new timeline's position, also without emitting seekComplete.

    • stop(): Promise<void>

      Stop playback and reset to the beginning.

      The position source is deactivated and the 'stop' event is emitted synchronously; a pending start() or seek() is cancelled. The active timeline actions are then ended, after transport commands called earlier; the returned promise resolves when their end operations have finished, or earlier when a later seek() or stop() takes over. A start() called after stop() waits for it. Errors in end operations are reported through the error event, not rethrown.

    switchTimeline

    • switchTimeline(uri: string, position?: number): Promise<void>

      Switch to a different timeline.

      First initialises the new timeline's position source and container provider on first use. If that fails, the current timeline is left as it was and the promise rejects, so a later call retries. Then it ends the active actions of the current timeline, activates the new timeline, seeks it to position, emits timelineChange, starts the actions that cover that position and starts playback (unless pause() or stop() was called after this call). The returned promise resolves when playback has started; it does not wait for start operations to finish. Failing actions are reported through the error event. Concurrent calls are processed one after the other. Switching to the current timeline does nothing.

      Parameters

      • uri: string

        Timeline URI to switch to

      • position: number = 0

        Optional starting position

      Returns Promise<void>

      Throws

      Error (rejects) when the engine is not initialised or no timeline has the URI
