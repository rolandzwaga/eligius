    Class Eventbus

    Central event bus for pub/sub communication and synchronous request/response queries.

    The eventbus supports:

    • Pub/Sub: on(), once(), off(), broadcast(), broadcastForTopic()
    • Request/Response: onRequest(), request(), requestForTopic() for synchronous queries
    • Interceptors: Transform event arguments before handlers receive them
    • Listeners: Global event observers for logging/debugging

    Example: Pub/Sub pattern

    const remover = eventbus.on('timeline-play', () => console.log('Playing'));
    eventbus.broadcast('timeline-play', []);
    remover(); // Unsubscribe

    Example: Request/Response pattern

    eventbus.onRequest('request-instance', (name) => new MyClass(name));
    const instance = eventbus.request<MyClass>('request-instance', 'test');

    Broadcasts isolate errors: a handler, listener or interceptor that throws, or returns a promise that rejects, is reported and the others still run. Request responders are not isolated; their errors reach the requester.

    Example: Observing handler errors

    const eventbus = new Eventbus({
      onHandlerError: (error, {eventName, eventTopic, source}) =>
        myLogger.warn(`${source} failed for ${eventName}`, error),
    });

    broadcast

    • broadcast(eventName: string, args: any[]): void

      Broadcast an event to its interceptors, the eventbus listeners and its handlers, in that order.

      Errors are isolated: a handler, listener or interceptor that throws (or returns a promise that rejects) is reported through console.error and the onHandlerError option, and the remaining ones still run. A failing interceptor leaves the arguments as they were before it ran. This method never throws because of them.

      Parameters

    request

    • request<K extends keyof RequestMap>(
          eventName: K,
          ...args: RequestMap[K]["args"],
      ): RequestMap[K]["returns"] | undefined

      Send a synchronous request and get an immediate response. Returns undefined if no responder is registered.

      For a name declared in RequestMap, called without an explicit type argument, the response is typed from the map.

      Unlike a broadcast, an error thrown by the responder is not caught: it propagates to the caller, which needs the response and has no other way to tell a failure from an undefined answer.
